# Medical Waiting List Card — full-stack Rust crate

Server-rendered full-stack implementation: Rust edition 2024, Loco 0.16
on axum 0.8, SeaORM 1.1 with PostgreSQL, Tera templates with HTMX 2.0.8
and Alpine.js 3.14.8.

See [`../../AGENTS/full-stack-with-loco-tera-htmx-alpine.md`](../../../AGENTS/full-stack-with-loco-tera-htmx-alpine.md)
for the shared stack conventions and the form-level
[`../AGENTS.md`](../AGENTS.md) for the data model.

## Bootstrap

Run the local bootstrap script to create the Loco project skeleton:

```sh
sh 00-new.sh
```

Then run the generated scaffold script at the form root:

```sh
../full-stack-with-loco-tera-htmx-alpine-setup
```

The scaffold script is regenerated by
[`bin/full-stack-with-loco-tera-htmx-alpine/generate-full-stack-with-loco-tera-htmx-alpine-setup.py`](../../../bin/full-stack-with-loco-tera-htmx-alpine/generate-full-stack-with-loco-tera-htmx-alpine-setup.py)
whenever the SQL migrations change.

## Tables scaffolded

Scaffolds are emitted in dependency order so foreign-key targets exist
before the referencing tables:

1. `patient`
2. `practitioner`
3. `medical_waiting_list_card`
4. `medical_waiting_list_card_appointment`
5. `medical_waiting_list_card_grade`
6. `medical_waiting_list_card_grade_rule`
7. `medical_waiting_list_card_grade_flag`

# UK LPA for Financial Decisions — Full Stack Backend (Agent Instructions)

Rust full-stack implementation of the LP1F deed and OPG registration
application as a single-page 15-step wizard with a validation engine
that fires statutory blocker rules and additional flags.

## Stack

- Rust edition 2024.
- Loco 0.16 framework on axum 0.8.
- SeaORM 1.1 with PostgreSQL.
- Tera templates server-rendered.
- HTMX 2.0.8 + Alpine.js 3.14.8 on the client.
- `serde(rename_all = "camelCase")` on Rust types shared with the
  front-end for JSON/JS interop.

## Directory map

- `Cargo.toml` — workspace + package manifest.
- `.gitignore` — `/target`, `.env`, local config overrides.
- `config/` — `development.yaml`, `test.yaml`, `production.yaml`.
- `src/` — application code:
  - `main.rs` and `bin/main.rs` — CLI entrypoint.
  - `lib.rs` — module declarations.
  - `app.rs` — Loco `Hooks` impl.
  - `controllers/` — one module per resource (`lpa.rs`, `person.rs`, …).
  - `models/` — SeaORM models per resource.
  - `views/` — Tera view helpers per resource.
- `templates/` — Tera templates:
  - `base.html.tera` — base layout (HTMX 2.0.8, Alpine.js 3.14.8, `hx-boost`).
  - `lpa/`, `person/`, `address/`, … — one subdir per resource with
    `list.html.tera`, `show.html.tera`, `new.html.tera`,
    `edit.html.tera`, `_form.html.tera`.
- `assets/` — `static/`, `i18n/`, `views/` for Loco template fallback.
- `migration/` — SeaORM migration crate (one migration per table).
- `tests/` — integration tests under `requests/`, `models/`, etc.
- `target/` — Cargo build output (kept as a tracked dir with `.gitkeep`).

## Scaffold workflow

The 16 SeaORM resources are generated by the form-level setup script:

```sh
forms/united-kingdom-lasting-power-of-attorney-for-financial-decisions/full-stack-with-loco-tera-htmx-alpine-setup
```

It calls `cargo loco generate scaffold <table> <col>:<type>[!^] … --htmx`
once per SQL table in dependency order. See the parent
[`AGENTS/full-stack-with-loco-tera-htmx-alpine-setup.md`](../../../AGENTS/full-stack-with-loco-tera-htmx-alpine-setup.md)
for the scaffold-DSL mapping.

## Validation engine

Rust port of the TypeScript engine
(`forms/.../front-end-form-with-svelte/src/lib/engine`). Same shape:
`validateLpa(input) -> { validityBand, compositeRisk, firedRules, additionalFlags }`.
Each fired rule must cite a statutory source (MCA 2005 / LPA Regs 2007).

## Routes

- `GET  /` — landing.
- `GET  /lpa` — list of LPAs.
- `GET  /lpa/new` — start a new LPA (15-step wizard).
- `POST /lpa` — create.
- `GET  /lpa/{id}` — show.
- `GET  /lpa/{id}/edit` — edit any step.
- `PUT  /lpa/{id}` — update.
- `DELETE /lpa/{id}` — soft-delete.
- `POST /lpa/{id}/validate` — run validator; renders validity-band card
  + fired-rules + additional-flags partials returned as HTMX swaps.
- Each child resource (`/lpa/{id}/attorneys`,
  `/lpa/{id}/people-to-notify`, etc.) provides nested CRUD for the
  related rows.

## Conventions

- camelCase JSON via `serde(rename_all = "camelCase")` on every shared
  struct.
- UUIDv4 primary keys; `created_at` + `updated_at` + `deleted_at`
  on every table.
- Empty string `''` for unanswered text/enum fields; `Option<NaiveDate>`
  / `Option<Decimal>` for unanswered date/numeric fields.
- snake_case for SQL columns and Rust struct fields; the
  `rename_all = "camelCase"` serde attribute provides front-end interop.
- `templates/base.html.tera` MUST contain the HTMX 2.0.8 CDN script tag,
  the Alpine.js 3.14.8 CDN script tag, and `<body hx-boost="true">` —
  `bin/test-form` greps for those three exact strings.

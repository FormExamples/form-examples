# Medical Operation Note - full-stack agent notes

Rust backend for the medical-operation-note wizard. Server-rendered with
HTMX + Alpine.js + Tera on a Loco/axum/SeaORM stack.

## Where the code lives

The Loco crate lives in `medical_operation_note/` (snake_case, matches
the canonical `pre_operative_assessment_by_clinician/` layout). The
outer `full-stack-with-loco-tera-htmx-alpine/` directory is a thin
shim: it carries `00-new.sh`, the four doc files, `templates/base.html.tera`
(for the bin/test-form contract) and a set of symlinks
(`Cargo.toml`, `src`, `tests`, `assets`, `config`, `migration`, `target`,
`.gitignore`) that re-export the inner crate to the path expected by
the test harness.

## Bootstrapping

```sh
cd full-stack-with-loco-tera-htmx-alpine
./00-new.sh                                              # databases + loco new -a (idempotent)
bash ../full-stack-with-loco-tera-htmx-alpine-setup     # scaffolds all 13 tables
```

Known quirks handled in the existing tree:

- The generated `full-stack-with-loco-tera-htmx-alpine-setup` script
  emits `:ts` for `TIMESTAMPTZ`, but Loco 0.16 only accepts `:tstz`.
  Re-run the setup through `sed 's/:ts /:tstz /g; s/:ts!/:tstz!/g'`
  before piping into a shell.
- `medical_operation_note.lead_surgeon_id` is a FK to `clinician.id`, but
  Loco's `lead_surgeon:references` shorthand assumes a `lead_surgeons`
  table. The generated migration was hand-fixed to use
  `("clinicians", "lead_surgeon_id")`.
- The starter `assets/i18n/en-US/main.ftl` from `loco new` references
  `$multi-word-param`, which is not valid Fluent. The view-engine
  initialiser now degrades gracefully on FTL parse errors so the app
  still boots if the locale files contain mistakes.

## Scoring engine

See `medical_operation_note/src/engine/`. The public surface is:

```rust
use medical_operation_note::engine::{grade, OperationNote};

let g = grade(&OperationNote { /* ... */ });
println!("{:?}", g.composite_risk);  // Routine | Complicated | HighRisk | Critical
```

`grade()` runs each sub-rule, takes the worst band as the composite,
collects fired rules, and emits safety flags via
`flagged_issues::collect`. All structs use `serde(rename_all = "camelCase")`
to interoperate with the SvelteKit front-end.

## Templates

`assets/views/operation_note/index.html` extends `base.html` and
`{% include %}`s the twelve step partials. There is no progress bar
and no inter-step navigation - the entire wizard is one page, per the
monorepo single-page rule.

The pinned CDN strings required by `bin/test-form` live in
`templates/base.html.tera` (a Tera-style mirror of the runtime base
that the test harness greps for).

## Conventions

- Edition 2024, axum 0.8, Loco 0.16, SeaORM 1.1
- snake_case in SQL/Rust internals; camelCase in serde-renamed structs
- UUIDv4 primary keys (auto-generated by Loco scaffold default)
- `created_at`, `updated_at`, `deleted_at` on every table
- Empty string `''` for missing text/enum, `None` for missing numeric/date/time

# united-states-hipaa-authorization-form — sql

PostgreSQL migrations for the HIPAA authorization form. See
`AGENTS/sql.md` for canonical conventions and
`../doc/hipaa-privacy-rule.md` for the regulatory text that drives the
schema.

## Canonical files

- `00_extensions.sql` — required extensions (pgcrypto).
- `01_create_function_set_updated_at.sql` — trigger function used by
  every `updated_at` column.
- `02_create_table_patient.sql` — patient identification.

## Form-specific tables

- `hipaa_authorization` — parent entity.
- `signer` — signer identification (§ 164.508(c)(1)(vi)).
- `disclosing_source` — person(s) authorized to disclose
  (§ 164.508(c)(1)(ii)).
- `authorized_recipient` — recipient(s) (§ 164.508(c)(1)(iii)).
- `records_to_disclose` — specific PHI description plus per-category
  yes/no/initials (§ 164.508(c)(1)(i)).
- `purpose_of_disclosure` — purpose(s) (§ 164.508(c)(1)(iv)).
- `expiration` — expiration date or event (§ 164.508(c)(1)(v)).
- `patient_rights_acknowledgement` — § 164.508(c)(2) statements.
- `signature_witness` — signature, date, witness, co-signature
  (§ 164.508(c)(1)(vi)).
- `validation_result` — engine output.
- `validation_fired_rule` — per-rule output.
- `validation_additional_flag` — priority-graded flags.

## Derived artefacts

- `schema.sql` — every migration concatenated (generated by
  `bin/sql/generate-sql-combined.py`).

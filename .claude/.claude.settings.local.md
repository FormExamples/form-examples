# ~/.claude/settings.local.json — Permission Rules Reference

Companion documentation for `~/.claude/settings.local.json`. Describes every
allow-rule currently configured, the rationale for what's in vs. out, and how
to extend or audit the list.

## What this file controls

`~/.claude/settings.local.json` holds **personal, user-level** Claude Code
settings — primarily the `permissions.allow` array. Entries in that array
tell Claude Code to run the matching tool calls **without prompting** for
approval. Anything not matched falls back to a prompt (or to deny, if a
`deny` rule matches first).

### Settings precedence

```
managed/policy  >  CLI flags  >  .claude/settings.local.json (project, gitignored)
                              >  .claude/settings.json       (project, committed)
                              >  ~/.claude/settings.local.json (user, local)
                              >  ~/.claude/settings.json     (user, global)
```

Later wins where rules overlap. `permissions.allow` arrays **union** across
sources rather than overriding — a permission granted at any level applies.

### Rule syntax

| Form                       | Matches                                          |
| -------------------------- | ------------------------------------------------ |
| `Read`                     | All Read operations                              |
| `Bash(npm test)`           | Exactly `npm test`                               |
| `Bash(git status:*)`       | `git status` and any suffix (`git status -sb`)   |
| `Bash(cargo build:*)`      | `cargo build`, `cargo build --release`, etc.     |
| `WebFetch(domain:foo.com)` | WebFetch tool against `foo.com`                  |
| `Read(/path/**)`           | Read under a directory tree                      |
| `Skill(name)`              | Invocation of skill `name`                       |
| `Skill(name:*)`            | Invocation of skill `name` with any args         |

The `:*` suffix is a **prefix wildcard**: anything starting with the literal
text (followed by whitespace or end-of-string) matches.

## Web access

### `WebSearch`

Allows the WebSearch tool unrestricted.

### `WebFetch(domain:<host>)` rules

Per-domain allowlist for the WebFetch tool. Currently allowed:

- `www.gov.wales`, `www.cvedetails.com`, `github.com`
- NHS Wales domains: `cmssupport.nhs.wales`, `dhcw.nhs.wales`,
  `www.nhs.wales`, `phw.nhs.wales`, `bcuhb.nhs.wales`, `elh.nhs.wales`
- `docs.masacms.com`, `www.cisa.gov`, `hub.docker.com`

These reflect prior research sessions; any other host still prompts.

### `Bash(curl ...)` rules

A set of pre-approved `curl` invocations against NHS Wales URLs, kept from
earlier sessions where each variant was approved once. They use the
`__TRACKED_VAR__` placeholder for varying URL paths. Not a wildcard — these
are exact-match strings (with Claude Code's URL-tracking substitution
applied). Remove them if no longer relevant.

## Git — read-only / inspection

Anything that **does not mutate working tree, history, or remote**. The few
edge cases:

- `git fetch:*` — updates refs in `.git`, but does not touch the working
  tree, so it's safe.
- `git branch:*` and `git tag:*` — match destructive variants too
  (`git branch -D foo`, `git tag -d v1`). If that bothers you, replace
  with `git branch --list:*` / `git tag --list:*`.
- `git config --get:*`, `--list:*`, `-l:*` — explicitly the read flags.
  Writing config still prompts.

A broad set of POSIX read/inspection utilities. All prefix-wildcarded.

## Auditing the list

Useful one-liners:

```bash
# Count entries
jq '.permissions.allow | length' ~/.claude/settings.local.json

# Show only Bash rules
jq -r '.permissions.allow[] | select(startswith("Bash("))' \
  ~/.claude/settings.local.json

# Show rules for a specific tool family
jq -r '.permissions.allow[] | select(test("Bash\\(git "))' \
  ~/.claude/settings.local.json

# Validate JSON syntax
jq -e . ~/.claude/settings.local.json > /dev/null && echo OK
```

## Applying changes

Edits to `settings.local.json` take effect:

- **Immediately** in new Claude Code sessions, OR
- **In the current session** after opening `/permissions` (reloads
  config), OR
- After restarting Claude Code.

A bare new permission rule won't apply mid-session until one of those
triggers — the watcher only watches directories that contained a settings
file when the session started.

## Removing a rule

Just delete its line from the JSON array, then either open `/permissions`
or restart. The rule reverts to prompting.

## Adding a rule safely

1. Start from a confirmed-safe pattern: read-only inspection commands are
   the lowest risk.
2. Prefer `Bash(<cmd> <subcommand>:*)` over `Bash(<cmd> *)` — the former
   constrains the subcommand, the latter allows any subcommand.
3. Never allow `sudo`, `eval`, `exec`, `xargs`, raw shell (`bash -c`), or
   anything that takes arbitrary commands as arguments — they bypass the
   rest of the allowlist.
4. After editing, validate with `jq -e . ~/.claude/settings.local.json`.

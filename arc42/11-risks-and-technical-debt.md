# 11. Risks and Technical Debt

| # | Risk / debt | Description | Mitigation / status |
| - | ----------- | ----------- | ------------------- |
| R1 | **Accessibility palette debt** | The Lily contract commits to WCAG 2 AA colour contrast on all interactive states, but the concrete theme palettes (light, dark, dim, and the vendored NHS/GDS/USWDS themes) are not all verified AA across every interactive state. Contrast is a *stated commitment* not yet fully proven per theme. | Treat AA verification per theme as outstanding; add automated contrast checks to the accessibility gate. |
| R2 | **Breadth of the 286-crate CI matrix** | Building and testing 286 independent Loco crates (plus two front-ends each) is expensive and prone to transient toolchain/sccache failures. A full matrix run is slow. | Batch builds; serial rerun recovers transient failures; per-form gates keep the blast radius to one form. |
| R3 | **Internationalization not yet rolled out** | i18n beyond an English + Welsh pilot is planned but not implemented; message extraction and the `assets/i18n/<locale>/main.ftl` pattern exist only in pilot form. Most forms are English-only. | Out of scope today (`spec.md` §2); pilot pattern documented; roll-out deferred. |
| R4 | **Deployment, authentication, and multi-tenancy out of scope** | No hosted environment, no auth, no multi-tenancy today. The `/metrics` endpoint is unauthenticated by default. Each crate is independently deployable but nothing is deployed. | Intended shape documented in [§7](07-deployment-view.md); production access controls deferred to the ingress/network layer. |
| R5 | **No unified backend** | 286 independent crates mean no cross-form querying, shared auth, or single deployment; operational overhead scales with form count. | Deliberate per-form independence ([§2.1](02-architecture-constraints.md)); revisit if a hosted product emerges. |
| R6 | **Engine triplication drift** | The scoring engine is implemented three times (HTML JS, Svelte TS, Rust). They can silently diverge despite shared rule/flag IDs. | Shared rule/flag ID discipline; unit tests per stack; the FHIR/example fixtures act as cross-checks. A cross-stack conformance harness would strengthen this. |
| R7 | **Fragile worktrees / generator-vs-layout skew** | Repo automation notes record that gitignored worktrees can vanish mid-task and that generators occasionally lag directory reorganisations (e.g. route-nesting, dir moves), producing transient drift. | Work in `main`; run generators after reorgs; drift gates catch stale output. |
